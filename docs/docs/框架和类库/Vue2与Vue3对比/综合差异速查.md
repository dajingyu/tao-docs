# Vue 2 与 Vue 3 综合差异速查

> 响应式专篇见：[响应式对比](./响应式对比.md)

## 生命周期对照（选项式）

```js
// Vue 2 选项式  →  Vue 3 选项式 / 组合式（常见对应）
beforeCreate  →  使用 setup()（组合式，无等价 beforeCreate）
created       →  使用 setup()
beforeMount   →  onBeforeMount
mounted       →  onMounted
beforeUpdate  →  onBeforeUpdate
updated       →  onUpdated
beforeDestroy →  onBeforeUnmount
destroyed     →  onUnmounted
errorCaptured →  onErrorCaptured
```

**说明**：组合式里没有 `beforeCreate` / `created`，逻辑直接写在 `setup` 顶层（或 `<script setup>` 顶层）即可。

与 `keep-alive` 相关的 `activated` / `deactivated` 在两版中名称一致。

## 核心差异清单

### 1. 卸载阶段命名

- Vue 2：`beforeDestroy`、`destroyed`
- Vue 3：`beforeUnmount`、`unmounted`

### 2. 组件通信与实例 API

- Vue 3 移除 **`$on` / `$off` / `$once`**，默认不再自带全局事件总线；可用 **`mitt`** 等库。
- Vue 3 移除 **`v-bind:xxx.sync`**，父子双向多用 **`v-model`**（或多组 `v-model:xxx`）。
- **`v-model` 在组件上**
  - Vue 2：常见为 **`value` + `input`**（或依实现而定）。
  - Vue 3：默认 **`modelValue` + `update:modelValue`**，可用 **`v-model:propName`** 自定义。
- Vue 3 移除 **`$listeners`**，相关行为并入 **`$attrs`**。
- Vue 3 移除 **`$children`**，访问子实例宜用 **`ref`**。

### 3. 模板指令

- **`v-for` 与 `v-if` 同节点时的优先级**
  - Vue 2：`v-for` 更高。
  - Vue 3：`v-if` 更高（不建议同节点混用，可读性差）。
- Vue 3 新增 **`v-memo`**（缓存部分 DOM）。
- Vue 3 移除 **`.sync`**（见上）。

### 4. 开发范式

- Vue 2：以**选项式 API**为主。
- Vue 3：选项式仍可用，并增加**组合式 API**（`setup` / `<script setup>`、`ref`、`reactive`、`watch`、`computed`、以 `on` 开头的生命周期等）。

### 5. 响应式实现

见 [响应式对比](./响应式对比.md)。

## 通信与全局 API 差异（补充）

以下在「概览类笔记」里常与通用通信写在一起，此处单独汇总为**版本差异**：

- **组件上的事件**
  - Vue 2：组件上监听默认多为**自定义事件**；监听原生 DOM 常需 **`.native`**。
  - Vue 3：满足条件时可为 **DOM 事件**（事件名须为 DOM 事件名、子组件有根、且未用 `defineEmits` 声明同名事件等）；否则为自定义事件。
- **全局事件总线**
  - Vue 2：常用 `$bus` 等自建总线。
  - Vue 3：无内置 `$on/$off`，多用 **`mitt`** 等。
- **`$attrs` / `$listeners`**
  - Vue 2：`$listeners` 单独存在。
  - Vue 3：无 `$listeners`，并入 **`$attrs`**。
- **`$parent` / `$children` / `$refs`**
  - Vue 3 无 **`$children`**，请用 **`ref`** 获取子组件实例。

状态管理习惯上：Vue 2 项目常见 **Vuex**，Vue 3 新项目常见 **Pinia**（二者也均可跨版本使用，以项目为准）。

## 虚拟 DOM 与更新策略（对照）

### 性能与编译

| 方面 | Vue 3 | Vue 2 |
| --- | --- | --- |
| 模板 | 编译期优化更多，减少运行时解析成本 | 更多依赖运行时解析 |
| VNode | 更轻量 | 相对更重 |
| 更新 | Patch 更细粒度，减少无效更新 | 相对粗放 |
| 包体积 | 更易 **Tree-Shaking** 去掉未用 API | 整体打包形态相对固定 |

### API 形态对 VDOM 的影响

- Vue 3 的**组合式 API**更利于逻辑复用与组织，间接影响渲染与更新路径的设计。
- Vue 2 以**选项式**为主，复杂场景下逻辑易分散在多个选项中。

### 与响应式的关系

- Vue 3：**Proxy** 响应式 + 更细的更新路径，常带来更可控的更新。
- Vue 2：**Object.defineProperty**，对新增属性等场景需额外 API 配合。

### Vue 3 在 Diff / 更新路径上的常见表述（补充）

- 更偏**增量**的更新策略，减少无效 DOM 操作。
- **静态提升**等编译优化：尽量让不变节点少参与 Diff。
- 对动态节点与 `key` 的追踪更细，便于局部**最小化**更新。
- 事件侦听等运行时代码路径相对 Vue 2 往往更省（以实际版本为准）。

## nextTick 差异（原理层面）

### Vue 2

为兼容旧浏览器，将回调放入异步队列时，会按能力依次尝试 **Promise → MutationObserver → setImmediate → setTimeout** 等方案。

### Vue 3

不再面向过旧浏览器时，可主要依赖 **Promise** 等现代方案；**不传回调**时，`nextTick()` 会返回 **Promise**，便于 `await`。

**记忆点**：Vue 2 的「多种 `timerFunc`」主要来自**兼容**；Vue 3 可更**简单、一致**。
